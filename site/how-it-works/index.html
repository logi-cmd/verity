Verity / How it works

From repository evidence to a machine result.

Verity answers one bounded question: can this selected target complete its declared run path on this recorded machine?

DetectPlanExecuteOracleResult

1. Detect from committed facts

Verity starts with runtime manifests, lockfiles, scripts, unique framework entry points, checked-in test configuration, and health declarations. README commands can explain a project to a person, but they do not become executable authority.

Detection produces logical targets. Product targets remain prominent while libraries, examples, fixtures, and workspace members stay available as advanced components.

2. Build a bounded plan

Each target receives three independent states:

  • plan completeness: whether every required command has traceable evidence;
  • environment compatibility: whether the current machine can supply the declared runtime;
  • oracle strength: whether the result can prove behavior rather than merely observe a process.

If a lock is missing, commands conflict, or the target has no adequate oracle, the plan reports that boundary before execution.

3. Execute the recorded snapshot

Verity fingerprints the repository and creates an isolated snapshot. Dependency acquisition is explicit. Build and test stages run without network access when the adapter contract allows it. Escaping symbolic links and source changes invalidate the run.

Some native targets require explicit confirmation because an isolated directory and process controls are not a hostile-code sandbox.

4. Observe a real machine oracle

A machine oracle is a target-specific behavioral result: a declared test suite, service health contract, non-empty HTML response, checked-in headless test, or equivalent repository evidence. A process starting, a port opening, or a window appearing is not sufficient.

Verity stops at the first observed blocker and preserves the difference between blocked, started but unverified, and verified.

5. Sign the local result

A verified receipt binds the result to the repository and snapshot fingerprints, target, recorded host, execution environment, oracle, and time. An Ed25519 signature makes later tampering detectable for the same local installation.

The signature is not remote attestation and does not certify that the source is safe. Read the complete receipt contract.

verity inspect C:\path\to\repository --json
verity check C:\path\to\repository --target TARGET_ID
verity receipt SESSION_ID
Verity: local run truth
