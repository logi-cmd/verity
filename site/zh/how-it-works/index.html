Verity / 工作原理

从仓库证据到机器结果。

Verity 只回答一个有边界的问题：所选目标能否在这台已记录的机器上完成仓库声明的运行路径？

检测计划执行Oracle结果

1. 从已提交事实检测

Verity 从运行时清单、锁文件、脚本、唯一框架入口、已提交测试配置和健康声明开始。README 命令可以帮助人理解项目，但不会自动成为执行依据。

检测会生成逻辑目标。产品目标优先显示，库、样例、fixture 与 workspace 成员保留为高级组件。

2. 生成有界计划

每个目标有三个互相独立的状态：

  • 计划完整性：每个必要命令是否有可追溯依据；
  • 环境兼容性：当前机器能否提供声明的运行时；
  • Oracle 强度：结果能否证明行为，而不只是观察到进程。

缺少锁文件、命令冲突或没有足够 Oracle 时，计划会在执行前明确报告边界。

3. 执行已记录快照

Verity 为仓库生成指纹并创建隔离快照。依赖获取需要明确发生。适配器契约允许时，构建和测试阶段会移除网络访问。逃逸符号链接或源仓库变化会使运行失效。

部分原生目标需要明确确认，因为隔离目录和进程控制不是恶意代码沙箱。

4. 观察真实机器 Oracle

机器 Oracle 是目标特定的行为结果，例如声明的测试套件、服务健康契约、非空 HTML 响应、已提交 headless 测试或同等仓库证据。进程启动、端口开放或窗口出现都不够。

Verity 在第一个观察到的阻塞处停止，并保留阻塞、已启动但未验证和已验证之间的区别。

5. 签名本机结果

已验证凭证绑定仓库与快照指纹、目标、宿主、执行环境、Oracle 和时间。Ed25519 签名使同一本机安装后续能够发现篡改。

签名不是远程证明，也不认证源代码安全。完整定义见凭证契约。

verity inspect C:\path\to\repository --json
verity check C:\path\to\repository --target TARGET_ID
verity receipt SESSION_ID
Verity：本机运行真相
