ONE BOUNDED JOB

Evidence first.
No project mythology.

01

Detect without guessing

Committed runtime declarations, locks, manifests, and unique framework entry points define the plan. README commands never auto-run.

02

Run the exact snapshot

Verity fingerprints the current files, rejects escaping symlinks, acquires dependencies with consent, then removes network access for build and test.

03

Require a real oracle

Tests, declared health checks, browser behavior, or checked-in smoke automation decide the result. A process or window alone stays unverified.

SECURITY & LIMITS

Strict about what
the result means.

Trusted source only. Verity is not a hostile-code sandbox. Native stages are isolated snapshots with process controls, not a malware boundary.

Zero guess-passes. Missing locks, ambiguous commands, snapshot changes, incomplete runtimes, and weak oracles stop the run.

Local signature only. A receipt is tamper-evident for this installation. It is not remote certification by Verity.

No upload interface. Raw receipts, repository paths, logs, source, and command output remain on the current machine.

OPEN LOCAL CORE

The tool that decides “verified” should be inspectable.

Desktop app, CLI, adapters, runner, and receipt logic are MPL-2.0. A future team control plane is separate and never required for local verification; raw receipts and run output stay local.
