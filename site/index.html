Evidence travels with every decision.

Verity does not run README snippets or infer what a project should do. Each stage is tied to committed declarations, an observed environment, and a result that can be explained later.

01

Detect the executable target

Locks, manifests, scripts, framework entry points, and checked-in test configuration produce a bounded plan. Ambiguity blocks the run.

02

Execute an isolated snapshot

The repository fingerprint is recorded before execution. Escaping links and source changes invalidate the run instead of being silently accepted.

03

Require a machine oracle

Declared tests, health checks, browser behavior, or checked-in smoke automation must pass. Process and port signals alone remain unverified.

04

Sign the bounded result

A verified receipt binds the result to its snapshot and environment with a local Ed25519 signature. It can be checked again without exposing logs or source.

Read support and limits

Strict about what verified means.

Trusted source only

Verity is not designed to contain hostile code or decide that unknown software is safe.

Snapshot bound

A repository change after the recorded run makes the receipt stale for the current files.

Local signature

The signature detects tampering for this installation. It is not remote attestation or third-party certification.

Local data

Raw receipts, paths, logs, source, and command output remain on the current machine.
